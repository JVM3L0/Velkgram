# Velkgram v0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn stored messages into browsable offers, give every wish a product page with price history and retroactive matches, and redesign the web UI in M3 Expressive with Catppuccin themes.

**Architecture:** A new hexagonal module `offers` subscribes to the ingestion events after `alerting`, builds one offer per message, and records wish matches. The pure deal rules move to `shared.deals` so `alerting` and `offers` share them. The web stays server-rendered (Jinja2 + HTMX), with Beer CSS for M3 components. Page data comes from query services that return plain view models (spec §4.4).

**Tech Stack:** Python 3.13, uv, FastAPI, Jinja2, HTMX 2.0.3, Beer CSS 5.0.3, SQLite with FTS5, pytest, ruff, pyright, import-linter.

**Spec:** `docs/superpowers/specs/2026-11-04-velkgram-v0.2.0-design.md` (builds on `docs/superpowers/specs/2026-11-04-velkgram-design.md`). Section references below such as "§6.3" point to the v0.2.0 spec. "v1 §x" points to the v1 spec.

- Real-time alert latency stays < 200 ms from handler to the first notify call, with the offers consumer subscribed (NFR1).
- No new runtime Python dependency and no build step (NFR4). Every CDN URL is pinned to an exact version:

## Plan-level rulings (deviations from the spec text, decided by the controller)

1. **`retro_runs.wish_version` becomes `fingerprint TEXT`.** Wishes carry no per-wish version, only the global `state_versions.wishlist`. The fingerprint is a SHA-1 of the wish's normalized required groups, excluded terms and max price. "Only changed wishes run" (§4.3) means "fingerprint differs from the stored run".
2. **Material Symbols come from the font Beer CSS 5.0.3 bundles,** not from Google Fonts. Only Roboto Flex is loaded from Google Fonts.
3. **The product page `/wishes/{id}` is served by the `offers` web router.** `offers` owns the data. Wish fields reach it through an injected callable. The wishlist router must be included **before** the offers router, so `/wishes/new` is not captured by `/wishes/{wish_id}`.
4. **"Tentar de novo" for a failed retroactive run:** the web deletes that wish's `retro_runs` row and bumps the `wishlist` state version (`shared.db.bump_version`). The collector picks it up within 3 s like any other wish change.
5. **Rebuild reads messages through an `offers` port `MessageSource`.** Its adapter wraps ingestion's public `IngestionQueries.iter_stored_messages`. `offers/services` never imports `ingestion`.
6. **`offers` gets a surrogate key.** `id INTEGER PRIMARY KEY` plus `UNIQUE (channel_id, message_id)`, instead of the §5 composite primary key. The FTS external content uses `content_rowid='id'`, which `VACUUM` never renumbers.
7. **Offer work never runs on the bus task.** The bus awaits every handler of event N before event N+1 reaches the evaluator, so any work inside a handler delays the next alert.
   - The `OfferBuilder` handlers only put the event on the builder's own unbounded `asyncio.Queue`. A worker task owned by the builder consumes it. A burst of backfill messages therefore never queues a live alert behind offer work.
   - The `WishlistChanged` handler only spawns the retroactive run (the existing `_spawn`/`_safe` pattern of `_on_channels_changed`).
8. **A `running` run found when no run is active is stale** (crash, restart or a stopped run). It is rerun. `failed` waits for the manual "Tentar de novo".
9. **Every wish, enabled or not, gets matches** (live, retroactive and rebuild alike), a deviation from FR10's "enabled". History has no gap for a paused period. Alerts still go only to enabled wishes; that is alerting's rule and does not change.
10. **Deleting a wish deletes its history at once.** The wishlist delete route calls an injected `on_deleted(conn, wish_id)`, wired by `apps` to `OfferRepository.delete_wish_data`. `wishes.id` has no AUTOINCREMENT, so without this a reused id would inherit the old wish's matches. The collector's cleanup in `RetroMatcher` stays as a backstop.
11. **Purged messages never overwrite offers.** When a message's text is empty and its offer already exists, `ingest` updates only the `sold_out` and `deleted` flags. Empty text is stored as `None`, never `''`.
13. **Rollout order: migrate, start the new collector, then `velkgram rebuild-offers`** (instead of §11's rebuild-then-restart). An old v1 collector running during the rebuild would ingest messages that never become offers. The rebuild is idempotent, so running it with the new collector up is safe.
14. **`offers.norm_text TEXT NULL`** stores `normalize_text(text)` next to `text` and is purged with it. Retroactive runs match on it directly, so they never re-normalize 180k texts (about 41 µs each).
12. **Reporting after retention.** The usage report (`texts_between`) only sees text from the last `RETENTION_DAYS`. Token-cost numbers for older dates undercount, and the README says so (Task 21).

## Review Focus

1. **Search input that is not a valid FTS5 query** (`"`, `-`, `*`, `AND`, `(`, a lone `'`) must return results or an empty page, never a 500. Pinned in Task 14 by `test_feed_search_tolerates_fts_syntax`.
2. **A post whose text is only emoji and links** must still get a title (the store name or "Oferta sem título"), never an empty card. Pinned in Task 3 by `test_title_falls_back_when_text_is_only_emoji_and_links`.
3. **A wish edited while its retroactive run is still running** must end with matches for the new terms only. Pinned in Task 9 by `test_edit_during_run_restarts_with_new_fingerprint`.
4. **A message link with a non-http scheme** (`javascript:`, `tg:`, `data:`) must never be rendered as a clickable `href`. Pinned in Task 17 by `test_feed_never_renders_non_http_links`.
5. **"Hoje" / "ontem" around midnight in `APP_TIMEZONE`.** A post at 02:00 UTC (23:00 on the previous day in São Paulo) seen at 03:30 UTC (00:30 local) reads "ontem 23:00", not "há 1 h". Pinned in Task 17 by `test_relative_time_uses_app_timezone`.

### Task 9: `RetroMatcher` service

**Spec:** FR11, NFR3, §4.3, §7. Plan rulings 1 and 4.
**Skills:** base only.
**Review skills:** `pr-review-toolkit:silent-failure-hunter`.

**Files:**
- Create: `velkgram/offers/services/retro_match.py`
- Test: `tests/offers/services/test_retro_match.py`

**Interfaces:**
`RetroMatcher(repo: OfferRepository, wishes: WishReader, clock: Clock, retention_days: int, sleep: Callable[[float], Awaitable[None]] = asyncio.sleep, chunk_size: int = 500)`:
- **`async on_wishlist_changed(_e: WishlistChanged) -> None`:**
  1. Delete the data (`delete_wish_data`) for every wish id that has a run but is no longer in `wishes.all()`.
  2. For every wish in `wishes.all()` (enabled or not) whose fingerprint differs from its stored run, or that has no run, `await self.run(wish)`.
  3. Errors per wish are isolated: they are logged and the next wish proceeds.
- **`async run(wish: WishView) -> None`:**
  1. Save a `running` run with the fingerprint.
  2. `since = now - retention_days`, then `delete_matches(wish.id, since)`.
  3. Iterate `iter_offers_with_text(since, chunk_size)` and match each row's `norm_text` with `shared.deals.matches`. Collect the matching offers of the chunk, and write them with one `add_matches([... source=retro ...])` call. Duplicates of live matches are skipped by the repository.
  4. `await self._sleep(0)` after every chunk.
  5. After each chunk, re-read the wish. If its fingerprint changed or it disappeared, stop. The next `WishlistChanged` restarts it.
  6. When done, save `done` with `finished_at`. On any exception, save `failed` with `error = type(exc).__name__`, log `retro_match_failed`, and do not re-raise.
- **Concurrency:** one run at a time. An `asyncio.Lock` serializes `on_wishlist_changed`.
- **Stale runs (ruling 8):** inside the lock no run is active, so step 2 also reruns every wish whose stored run is `running`. `failed` runs are not rerun automatically.
- **Who triggers the restart:** `run` does not loop. Step 5 stops the run and returns; the caller (the collector's change poll) calls `on_wishlist_changed` again on the next change.

- **`SqliteOfferQueries(conn)`:**
