# Velkgram v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers also load the project skill `velkgram-task` (it pulls in `velkgram-architecture`, `velkgram-conventions`, `velkgram-testing`).

**Goal:** Real-time (< 10 s) wishlist alerts from Telegram deal channels, with a web UI for wishes and channels, raw collection of every message, and a usage report.

**Architecture:** Modular monolith with hexagonal modules (`channels`, `wishlist`, `ingestion`, `alerting`, `reporting`) plus `shared` and `apps`. It runs as two processes (`collector`, `web`) over one SQLite database in WAL mode. Modules talk through plain-data events on an in-memory `EventBus` and through public APIs. `import-linter` enforces the boundaries.

**Tech Stack:** Python 3.13, uv, hatchling, Telethon, FastAPI + Jinja2 + HTMX, SQLite (stdlib `sqlite3`), pytest + pytest-asyncio, ruff, pyright (gating), ty (informational), import-linter, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-04-velkgram-design.md`. Each task cites the sections it implements, and implementers read only those sections.

## Global Constraints

- Python `>=3.13`. uv manages the interpreter (`uv python install 3.13`).
- Every repo artifact is in English. User-facing text (alert bodies, web UI) is in Portuguese (pt-BR).
- Money: integer cents, BRL. Time: aware UTC `datetime`, ISO-8601 in SQLite. "Now" comes only from the `Clock` port.
- Channels are added by `@username` or `t.me` link, then keyed by numeric `telegram_id` (`-100…`). Only broadcast channels are accepted.
- Dedup window: **30 min**. Backfill cap: **6 h or 200 messages per channel**. Backfilled messages alert only if younger than **30 min**.
- Polling intervals: change signal **3 s**, gap check **10 min**, failed-alert retry **1 min**, heartbeat and connection watcher **30 s**.
- Notifier: **3 attempts**, waiting **1 s** then **3 s** between them, each attempt with a **1.5 s** timeout. Notification runs as a background task and never blocks evaluating the next message.
- Latency is measured when the first `notify` call starts: `latency_telegram_ms = now − date`, `latency_internal_ms = now − handler entry`, both clamped at ≥ 0.
- SQLite: WAL, `busy_timeout=5000`, `check_same_thread=False`. Writes to wishes or channels bump `state_versions` **in the same transaction**. The web opens one connection per request.
- Flood waits ≤ **60 s** are slept automatically, and longer ones are logged and deferred. Silent-channel default: **12 h**.
- Internal critical-path budget: **< 200 ms**.
- Secrets come only from env (spec §9) and are never logged or committed.
- Module boundaries per spec §4.3 rules 1–7, enforced by `lint-imports`.

## Review Focus

1. **Photo-only post, or empty text:** nothing alerts and nothing crashes. A photo with a matching caption and no price → `price_unknown` alert. *(Task 12: `test_empty_text_never_alerts`, `test_caption_without_price_alerts_price_unknown`.)*
2. **Same deal, different price spellings** (`R$ 1.299,00`, `R$1299`, `por 1299`): the same cents, so suppressed. *(Task 6: `test_spellings_extract_same_cents`; Task 12: `test_reposted_with_other_price_spelling_is_suppressed`.)*
3. **Wish disabled while the collector runs:** no alert after the reload, and no crash. *(Task 16: `test_disabled_wish_stops_alerting_after_reload`.)*
4. **Telegram `date` later than our clock:** the latency fields are clamped to 0. *(Task 12: `test_latency_is_clamped_to_zero_on_clock_skew`.)*
5. **Album posts** (only one item has the caption): exactly one alert. *(Task 12: `test_album_items_without_caption_do_not_alert`.)*

## Orchestration Notes

- **Loop:** sequential, in table order. Each implementer subagent loads `velkgram-task` and receives its task block, the cited spec sections, and the Interfaces blocks of every task in its "Depends on" column. A reviewer subagent checks the finished task against its block, the spec and the `velkgram-*` skills before the next task starts.
- **Models:** implementers use the table's model. Reviewers use `haiku` for Task 22 and `sonnet` for the rest. Opus/Fable/forks are blocked by the project hook.
- **Budget:** never pass the whole plan. On `BLOCKED`, the orchestrator resolves it or asks the user, and never retries blindly. After 2 failed review rounds on one task, stop and ask the user.
- **Branch:** `feat/velkgram-v1` from `docs/velkgram-v1-design`. One commit per task. Never push.
- **Known limitations (accepted for v1):**
  - A message missed silently, with an id below a later live id, isn't detected by the gap check.
  - Sync SQLite calls run on the event loop, so a web write lock can delay ingestion by up to `busy_timeout` (5 s). This is rare with one user.
- **Ports exempt from the "fake + contract suite" rule:** `TelegramGateway` (fake only, plus adapter tests with a mocked client), `Notifier` (fake only), and `IngestionQueries`/`AlertQueries` (SQLite-only, tested directly on a temp DB).
